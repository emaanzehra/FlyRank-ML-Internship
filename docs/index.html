Content Decline Detection in Managed SEO Portfolios

Can a machine learning model identify declining content pages more reliably than a hand-crafted rule?

Emaan Zehra August 2026 Lane 2: Refresh/Content Opportunity Scoring GitHub Repo

Abstract

Content reviewers in managed SEO portfolios face a fixed-capacity problem: they can only action a limited number of pages per week. This study asks whether a Random Forest model can prioritize declining content pages more reliably than a hand-crafted staleness rule. Using 141,902 content pages from the FlyRank/internship-warehouse (June 2026), we trained a Random Forest on five GSC-derived features, using a within-month impression trend as the decline label. On a random holdout, Precision@50 reached 0.960 versus a baseline of 0.620. Under a grouped client split, the honest generalization test, Precision@50 dropped to 0.420. The central finding is methodological: random-split scores are inflated by client leakage. The model finds real signal, but its production readiness requires a future-window label and client-grouped validation.

01 Problem Statement

A content reviewer has a fixed queue. They can only action a limited number of pages per week. The question is: which pages should be reviewed first?

A hand-crafted rule flagging stale, visible pages provides a reasonable baseline. This study asks whether a machine learning model can identify declining pages more reliably, so reviewers spend time on the highest-value targets before decline becomes expensive to reverse.

Label definition

is_declining = 1 if week 4 impressions (June 24 to 30) are less than week 1 impressions (June 1 to 7). This is a within-month proxy for content decline, not a forward-looking forecast.

Features used

Performance signals
  • impressions_90d: total GSC impressions, June
  • avg_position: average GSC position, June
  • ctr: clicks divided by impressions, June
Content metadata
  • word_count: static, from dim_content
  • days_since_last_update: days since content_updated_date as of 2026-07-01

Exclusions

  • active_days: only 7 unique values across 141K rows, caused zero-variance clusters in the top 50 model predictions
  • avg_position values near 73.90: warehouse placeholder values not representing real search positions
  • avg_position = 0: pages with no position data
  • Rows where week1 or week4 impressions were null: pages with incomplete June coverage

03 Methodology

Model

Random Forest (n_estimators=200, max_depth=8, random_state=42). Selected because it handles mixed feature types without scaling, produces a probability score suitable for ranking, and captures non-linear interactions between signals. Resistant to the outliers common in content performance metrics.

Baseline (ML-06)

Hand-crafted rule: stale x visible x impressions_90d, where stale is defined as days_since_last_update greater than 30 and visible as avg_position at most 50. Pages scored above zero are flagged and ranked by score descending.

Validation design

Random split (ML-08)
  • 80/20 holdout, stratified on is_declining
  • Rows from same clients appear in both train and test
  • Optimistic: model learns client-specific patterns
Grouped client split (ML-09)
  • 43 train clients, 11 test clients
  • All rows from a client go entirely to one split
  • Honest: tests generalization to unseen clients

Leakage audit

impressions_90d and avg_position share the June 2026 window with the label. This creates mild descriptive overlap but no future data is used. word_count and days_since_last_update are static metadata with no window overlap. All feature-label Pearson correlations are below 0.05, confirming no strong direct leakage. The model is descriptive of within-period patterns, not predictive of future ones.

05 Limitations

Within-period label

The label measures a June dip, not future decline. A page that dropped in week 4 may recover naturally in July.

Single month snapshot

Only June 2026 data is available. Seasonal effects cannot be separated from structural decline.

Client leakage in random split

The 0.960 score is inflated. The honest grouped-client estimate is 0.420, a significant gap.

Label proxy limitations

GSC impressions only. Algorithm updates, seasonality, and competitor changes are not captured.

Feature window overlap

impressions_90d and avg_position share the label window. The model is descriptive, not forward-looking.

No causal claims

All results are observational. High days_since_last_update importance does not mean updating content will reverse decline.

06 Ranked Recommendations

Ranked by confidence in the observed signal, from strongest to most exploratory.

1
Use days_since_last_update as the primary triage signal
Observed: recently updated pages were less likely to show within-month impression decline (feature importance 0.35). Flag pages not updated in 30 or more days that still carry meaningful impressions as first refresh candidates.
2
Prioritize high-impression declining pages
A declining page with 5,000 impressions is a more valuable recovery target than one with 50. Sort the refresh queue by impressions_90d descending within the flagged set.
3
Do not use the random-split score for production decisions
Random-split Precision@50 = 0.960 drops to 0.420 under a grouped client split. Any production deployment must be validated on held-out clients, not held-out rows from the same clients.
4
Treat the model score as a triage rank, not a diagnosis
15,787 false negatives were missed because they look unremarkable across all features. Use the model to prioritize the first 50 pages for human review, not to replace review entirely.
5
Rebuild the label from a future window before production use
Use June features to predict July decline. Re-run the pipeline when July warehouse data is available. This makes the model genuinely predictive rather than descriptive.
